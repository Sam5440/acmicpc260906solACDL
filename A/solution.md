# A. 回忆

## 题意

原来有一个栈，支持三种操作：压入 x、查询 x 是否在栈中、弹出栈顶。

现在记录里只保留了压入和查询结果，其中 true 查询写成 T x，false 查询写成 F x，所有弹栈操作都丢失了。我们要把若干个弹栈操作插回去，使得整个过程合法，并输出只由加号、问号和减号组成的操作串。

合法要求有两个：任意时刻栈内不能有重复元素；每个 T/F 查询结果必须和记录一致。

## 关键观察

考虑某一次压入 x 后，栈里的这一份 x。

它什么时候必须离开？

- 如果后面再次压入 x，旧的 x 必须在新的 x 进栈前离开，否则栈里会有重复元素。
- 如果后面出现 F x，旧的 x 必须在这次查询前离开，否则查询结果会变成 true。

所以我们把下一次“压入 x 或 F x”的位置记为 deadline，这份 x 必须在 deadline 之前弹出；如果不存在，就记成 n+1。

它也不能太早离开：在 deadline 之前，所有 T x 都要求它仍在栈中。因此只需要知道 deadline 前最后一次 T x 的位置，记为 needAliveUntil。只要过了这个位置，这份 x 就再也不需要为了 true 查询保留。

这两个量可以从右往左扫描得到：对每个值维护“下一次压入或 F 的位置”和“当前段里最靠后的 T 的位置”。

## 贪心构造

从左往右模拟真实栈。栈里每个元素额外保存两个量：

- needAliveUntil：它最后一次必须还在栈里的位置；
- forcedPopBy：如果保持当前栈的上下关系，当前栈顶最晚必须在什么位置前弹出。它等于自己和所有下方元素的 deadline 最小值，因为想弹出下面的元素，必须先弹出上面的元素。

处理每条记录前，先做安全清理：只要栈顶的 needAliveUntil 已经小于当前位置，就说明它以后再也不需要回答 true 查询，可以立即弹出。

然后分情况处理。

### 压入 x

如果旧的 x 还在栈中，为了保持元素互异，必须一直弹到旧的 x 被弹掉。

接着看当前栈顶。新压入的 x 需要一直活到自己的 needAliveUntil；如果当前栈顶的 forcedPopBy 不晚于这个位置，那么它或它下面的某个元素必须在新 x 仍需存在时被弹出。由于新 x 一旦压上去会挡住它们，所以必须现在先弹掉。

完成这些必要弹栈后，压入新的 x，输出加号。

### F x

如果 x 还在栈中，为了让查询结果为 false，必须一直弹到 x 离开。然后输出问号。

### T x

直接输出问号。按上面的维护方式，合法输入中 x 此时一定还在栈里。

最后把栈清空。题目允许在记录末尾继续插入弹栈操作，这样输出形式稳定，也能和样例逐字节一致。

## 正确性说明

安全清理只弹出已经过了最后一次必须为 true 查询的栈顶元素，不会影响后续查询。

遇到压入 x 或 F x 时，如果旧的 x 还在栈中，那么旧 x 以及它上方的元素在任何合法方案中都必须先离开；否则要么出现重复元素，要么 F 查询不成立。

处理压入时额外检查 forcedPopBy：若某个当前栈顶最晚必须在新元素的 needAliveUntil 之前弹出，而新元素又必须活到 needAliveUntil，那么不提前弹出就会形成无法解决的栈顺序冲突。因此提前弹出是必要且安全的。

所以整个过程中，栈内始终没有重复元素；所有 F 查询前目标元素都不在栈中；所有 T 查询前目标元素不会被过早弹出。输出操作串合法。

## 复杂度

每个记录元素最多入栈一次、出栈一次。离散化需要排序。

- 时间复杂度：O(n log n)。
- 空间复杂度：O(n)。
