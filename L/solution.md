# 题目 L：Longest Common Prefix 题解

## 一、题意（大白话）

依次给你 `n` 个小写字符串，**每读进来一个**，都要回答一个问题：

> 假设现在已经有了前 `i` 个串。对于每个 `j = 1..i`，从这 `i` 个串里**恰好挑 j 个**，能让它们的"最长公共前缀（LCP）"最长是多长？把这个最大值记作 `f_j`。
> （规定：只挑 1 个串时，它的 LCP 就是它自己，长度就是串长。）
>
> 答案 = `(f_1 XOR 1) + (f_2 XOR 2) + ... + (f_i XOR i)`，其中 XOR 是按位异或。

举个样例 1 的例子。串依次是 `a, ab, abc, abcd`。

- `i = 1`：只有 `a`。挑 1 个，LCP 就是 `a` 本身，长 1。答案 = `1 XOR 1 = 0`。
- `i = 2`：有 `a, ab`。
  - 挑 1 个：最长的是 `ab`，`f_1 = 2`；
  - 挑 2 个：只能两个都挑，公共前缀是 `a`，`f_2 = 1`。
  - 答案 = `(2 XOR 1) + (1 XOR 2) = 3 + 3 = 6`。
- `i = 4`：有 `a, ab, abc, abcd`，`f = [4, 3, 2, 1]`（挑 j 个最长串，公共前缀长度恰好是 5-j）。
  答案 = `(4^1)+(3^2)+(2^3)+(1^4) = 5+1+1+5 = 12`。✔ 与样例输出一致。

数据范围：`n ≤ 5·10^5`，所有串的总长度 `Σ|s| ≤ 5·10^5`。所以"每个字符只做 O(1) 次工作"的算法才能过。

## 二、关键观察

### 观察 1：公共前缀 = trie 上共同经过的节点

把所有串插进一棵**字典树（trie）**：从根出发，每个字符往下走一条边。比如 `ab` 和 `abc` 会共用 "根→a→b" 这条路。

一个事实：**j 个串有长度为 d 的公共前缀** ⟺ **trie 上某个深度为 d 的节点，被这 j 个串都经过**。

所以，对每个 trie 节点 `u` 记一个计数 `cnt[u]` =（当前已插入的串中，有多少个经过 `u`）。那么：

> `f_j` = 所有满足 `cnt[u] ≥ j` 的节点 `u` 的**最大深度**。

直观理解：`cnt[u] ≥ j` 说明有至少 j 个串都走过 `u`，随便挑 j 个，它们至少共享 `u` 对应的那段前缀（长度 = `u` 的深度）。反过来，任何 j 个串的公共前缀也一定对应某个这样的节点。

### 观察 2：插入一个串，只有**一个位置**的 f 会变化（这是本题最核心的一步）

插入一个新串时，它路径上每个节点的计数 +1。看路径上深度为 `d` 的节点，它的计数从 `c-1` 变成 `c`。按观察 1，这个节点现在"够格"为所有 `j ≤ c` 提供深度 `d` 了。

但仔细想想：

- 对于 `j < c`：上一轮它的计数是 `c-1`，**已经**满足 `cnt ≥ j` 了，深度 `d` 早就被 `f_j` 考虑过了 —— `f_j` 不会因为它再变；
- 只有 `j = c`：这是它**第一次**凑够 `c` 个串，`f_c` 才可能因为它变大。

**结论：每次计数 +1，只需要做一次点更新 `g[c] = max(g[c], d)`**（`g[j]` 表示当前前 `i` 个串下的 `f_j`）。

（题目提示里说的"对所有 `j ≤ c` 取 max"也对，但对 `j < c` 那些全是空操作，真正生效的只有 `j = c` 这一个点。所以不需要区间 map，一个数组就够。）

### 观察 3：答案可以增量维护

我们维护当前答案 `ans = Σ (g[j] XOR j)`。

- 每开始插入第 `i` 个串，`j` 的范围多出一个位置 `j = i`，此时 `g[i] = 0`（还没有任何节点凑够 `i` 个串），贡献是 `0 XOR i = i`，所以 `ans += i`；
- 每次点更新把 `g[c]` 从 `old` 提到 `d`，只需 `ans += (d XOR c) - (old XOR c)`。

每次更新 O(1)，连求和都不需要重新扫描。

## 三、算法步骤

1. 建一棵空 trie（用数组 `ch[节点][26]` 存边），每个节点带计数 `cnt`，初始全 0；`g` 数组全 0；`ans = 0`。
2. 对 `i = 1..n`：
   a. `ans += i`（新位置 `j = i`，`g[i] = 0` 的贡献）；
   b. 把第 `i` 个串逐字符插入 trie：走到深度 `d = k+1` 的节点 `u`，`cnt[u] += 1`，记新值为 `c`；
      若 `d > g[c]`，则 `ans += (d XOR c) - (g[c] XOR c)`，`g[c] = d`；
   c. 输出 `ans`。

用样例 1 完整走一遍（`g` 从全 0 开始，`^` 表示异或）：

| 步骤 | 操作 | 深度 d / 新计数 c | g 变化 | ans 变化 | ans |
|---|---|---|---|---|---|
| i=1, 串 `a` | 新位置 | — | — | `+1` | 1 |
| | 节点 `a` | d=1, c=1 | g[1]: 0→1 | `+(1^1)-(0^1) = -1` | **0** ✔ |
| i=2, 串 `ab` | 新位置 | — | — | `+2` | 2 |
| | 节点 `a` | d=1, c=2 | g[2]: 0→1 | `+(1^2)-(0^2) = +1` | 3 |
| | 节点 `ab` | d=2, c=1 | g[1]: 1→2 | `+(2^1)-(1^1) = +3` | **6** ✔ |
| i=3, 串 `abc` | 新位置 | — | — | `+3` | 9 |
| | 节点 `a` | d=1, c=3 | g[3]: 0→1 | `+(1^3)-(0^3) = -1` | 8 |
| | 节点 `ab` | d=2, c=2 | g[2]: 1→2 | `+(2^2)-(1^2) = -3` | 5 |
| | 节点 `abc` | d=3, c=1 | g[1]: 2→3 | `+(3^1)-(2^1) = -1` | **4** ✔ |
| i=4, 串 `abcd` | 新位置 | — | — | `+4` | 8 |
| | 节点 `a` | d=1, c=4 | g[4]: 0→1 | `+(1^4)-(0^4) = +1` | 9 |
| | 节点 `ab` | d=2, c=3 | g[3]: 1→2 | `+(2^3)-(1^3) = -1` | 8 |
| | 节点 `abc` | d=3, c=2 | g[2]: 2→3 | `+(3^2)-(2^2) = +1` | 9 |
| | 节点 `abcd` | d=4, c=1 | g[1]: 3→4 | `+(4^1)-(3^1) = +3` | **12** ✔ |

四行输出 `0, 6, 4, 12`，与样例完全一致。

## 四、为什么是对的（直观说明）

- **观察 1 的正确性**：若深度 `d` 的节点 `u` 有 `cnt[u] ≥ j`，就真有 j 个串共享长 `d` 的前缀，所以 `f_j ≥ d`；反过来，任何 j 个串的最长公共前缀路径的终点，就是一个被这 j 个串都经过的节点，所以 `f_j` 不会漏掉更优的值。两边一夹，`f_j` 恰好等于"计数 ≥ j 的节点的最大深度"。
- **观察 2 的正确性**：节点计数从 `c-1` 涨到 `c`，对 `j ≤ c-1` 它本来就在"够格集合"里（深度不变），对 `j ≥ c+1` 它依然不够格，唯一变化的是它新加入了 `j = c` 的候选，因此 `g[c]` 与 `d` 取 max 就完整反映了这次变化。
- **增量答案的正确性**：每次只改 `g[c]` 一个位置，和式里也只有 `(g[c] XOR c)` 这一项变化，所以 `ans += 新项 - 旧项` 精确维护了总和。

## 五、复杂度

- 时间：每个字符引起恰好一次 trie 行走 + 一次 O(1) 点更新，共 `O(Σ|s| + n)`，约 `10^6` 次操作，绰绰有余。
- 空间：trie 节点数 `≤ Σ|s| + 1`，每个节点存 26 个 int 的边，约 `5·10^5 × 26 × 4B ≈ 52MB`；外加计数和 `g` 数组各 2MB。

## 六、验证

- 两个样例均精确通过（输出逐字节一致）。
- 写了暴力程序 `brute.cpp`（对每个 `i` 枚举全部 `2^i` 个子集取最大 LCP），与正解在 2000 组随机小数据（n ≤ 10，覆盖纯随机 / 全相同 / 链式 / 基串变异 / 单字符 / 重复串等形态，字符集含 {a,b}、{a,b,c}、a~z）上对拍，全部一致。
- 另外构造了大数据自测：`n=5·10^5` 全 `a`；`n=1` 单串长 `5·10^5`；链 `a, aa, ..., a^999`；25 万个 `ab`；总长 `5·10^5` 的大随机；1000 个串共享 300 长前缀。程序运行均在毫秒级，且结果通过独立公式抽验（如全 `a` 时 `f_j = 1`）。
